# Лабораторная работа № 4. Модульное тестирование

## 1. Цели и задачи тестирования

Проверить, что функции площади и периметра дают правильные результаты для квадрата и круга. Для каждой функции рассчитать эталоны вручную, сравнить их с выводом программы и закрепить те же примеры в повторяемых модульных тестах.

## 2. Описание тестируемого продукта

| Модуль | Вход | Функция `area` | Функция `perimeter` |
|---|---|---|---|
| `square.py` | Длина стороны a | Площадь квадрата, a² | Периметр квадрата, 4a |
| `circle.py` | Радиус r | Площадь круга, πr² | Длина окружности, 2πr |

Если размер указан в сантиметрах, площадь измеряется в см², а периметр — в см.

## 3. Область тестирования

Проверяются все четыре функции. Для каждой выбран нулевой размер как нижняя граница, целый размер 3 и дробный размер 0,5. При радиусе 3 площадь и длина окружности различаются, поэтому пример позволяет обнаружить подмену одной формулы другой. Поведение при отрицательных размерах и нечисловом вводе в задании не определено.

## 4. Стратегия тестирования

Сначала подставить размер в формулу и записать ожидаемое значение. Затем вызвать одну функцию с этим аргументом и сравнить ответ с эталоном. Для выбранных размеров квадрата и нулевого радиуса используется точное числовое сравнение. Для ненулевого радиуса допускается расхождение из-за представления π в формате `float`.

Автоматические проверки объединены в классы `SquareTestCase` и `CircleTestCase`, унаследованные от `unittest.TestCase`. Каждый метод `test_...` проверяет один результат через `assertEqual` либо `assertAlmostEqual(..., places=12)`. Во втором случае разность округляется до 12 знаков после запятой и должна дать ноль.

## 6. Критерии приёмки

Все 12 ручных проверок должны дать ожидаемый результат с указанной точностью. Команда запуска из каталога проекта должна выполнить 12 модульных тестов и завершиться со статусом `OK`.

```console
python -m unittest -v square.py circle.py
```
